# Analysis Directory

This directory contains work-in-progress analysis, IDA automation, and data samples for the Falcon 3.0 reverse engineering project.

## Directory Structure

### `ida_scripts/`
**IDA automation scripts**

The most important directory. Contains:
- `apply_known_names.py` - **MASTER** function name registry
- Scripts for extracting functions, data, and structures from IDA
- Quick reference guide

**See**: `ida_scripts/README.md`

### `ida_falconcd/`
**IDA Pro database and exports**

Contains:
- `FALCONCD.EXE.i64` - Main IDA database (the source of truth)
- Exported JSON data from batch processing
- Analysis artifacts from IDA

**Warning**: Do not manually edit these files. Use IDA automation scripts.

### `sessions/`
**Per-session work notes (temporary)**

Daily or per-task work notes that haven't been promoted to permanent documentation yet.

**Contents**:
- Hypotheses and experiments
- Debugging traces
- Work-in-progress findings

**Lifecycle**: 
1. Create session notes during analysis
2. When complete, promote findings to `docs/`
3. Archive old session notes

**See**: `sessions/README.md`

### `data_samples/`
**Extracted game data and visualizations**

Binary data extracted from game files for analysis:
- `isldat/` - Island terrain data (SVG visualizations, extracted geometry)
- `ai_contexts/` - AI memory dumps from running game
- `mission_files/` - Parsed mission and campaign data

**See**: `data_samples/README.md`

### `tools/`
**Analysis helper scripts**

Python scripts for parsing, extracting, and analyzing game data:
- `data_parsers/` - Parse binary formats (mission files, data files)
- `data_extractors/` - Extract data from game files or memory dumps
- Address translation utilities
- Segment mapping tools

**See**: `tools/README.md`

### `archive/`
**Historical and superseded files**

Old versions, superseded analyses, and completed session notes:
- `old_sessions/` - Historical session notes
- `old_analyses/` - Superseded analysis documents
- `output_files/` - Old .txt and .log output

**Note**: These files are historical. Check `docs/` for current documentation.

**See**: `archive/README.md`

## Key Files

### `ida_naming_report.json`
**Latest IDA synchronization results**

Generated by `ida_scripts/apply_known_names.py`. Shows:
- How many functions were renamed
- Which functions are already correct
- Which renames failed

Check this after running IDA synchronization.

### `CLEANUP_TASK.md`
**Future cleanup and organization tasks**

A backlog of cleanup work that can be done when time permits.

### `REORGANIZATION_PLAN.md`
**This reorganization's plan and rationale**

Documents why and how this directory was reorganized.

## Workflow

**See the main `WORKFLOW.md` file in the repository root.**

Quick reference:
1. **Learn**: Reverse engineer in IDA
2. **Document**: Write findings in `docs/<system>/`
3. **Rename**: Update `ida_scripts/apply_known_names.py`
4. **Commit**: Commit docs + script + report together

## Finding Things

### "Where should I put X?"

| Type | Location |
|------|----------|
| Permanent system documentation | `docs/architecture/` or `docs/systems/` |
| File format specification | `docs/data_formats/` |
| IDA function names | `ida_scripts/apply_known_names.py` |
| Session work notes | `sessions/<date>_<topic>/` |
| Extracted data samples | `data_samples/<category>/` |
| Analysis scripts | `tools/data_parsers/` or `tools/data_extractors/` |
| Old/superseded files | `archive/` |

### "Where is X?"

| Looking for | Check |
|-------------|-------|
| Function addresses and names | `ida_scripts/apply_known_names.py` |
| System architecture | `docs/architecture/<system>.md` |
| Data format spec | `docs/data_formats/<format>.md` |
| How to do something | `WORKFLOW.md` (root) |
| IDA automation | `ida_scripts/README.md` |
| Session notes | `sessions/` or `archive/old_sessions/` |
| Analysis scripts | `tools/` |

## Maintenance

### Weekly
- Review session notes, promote complete findings to `docs/`
- Run IDA synchronization if new functions discovered
- Check that `ida_naming_report.json` shows good results

### Monthly
- Archive old session notes
- Clean up `data_samples/` (remove obsolete data)
- Review and update this README if structure changes
