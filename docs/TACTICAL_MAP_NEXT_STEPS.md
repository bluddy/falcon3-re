## VGA Mode 13h Architecture

### Screen Layout
```
Resolution: 320x200 pixels
Colors: 256 (1 byte per pixel)
Segment: 0xA000:0000
Size: 64,000 bytes (320 * 200)
Addressing: Linear (offset = Y * 320 + X)
```

### Memory Map
```
0xA000:0000 - 0xA000:F9FF  (64,000 bytes)
  Row 0:   0xA000:0000-013F  (320 bytes)
  Row 1:   0xA000:0140-027F  (320 bytes)
  ...
  Row 199: 0xA000:F860-F9FF  (320 bytes)
```

### Pixel Calculation
```asm
; Pixel offset = Y * 320 + X
mov ax, Y           ; Load Y coordinate
mov dx, 320         ; Screen width
imul dx             ; AX = Y * 320
add ax, X           ; AX = Y * 320 + X
mov di, ax          ; DI = offset

; Alternative (faster): Y * 256 + Y * 64 = Y * 320
mov ax, Y
shl ax, 8           ; Y * 256
mov bx, Y
shl bx, 6           ; Y * 64
add ax, bx          ; Y * 320
add ax, X
```

### Phase 5: Analyze Coordinate Math (45 minutes)

Disassemble waypoint_coordinate_processor line by line:

#### Expected Algorithm Pattern

```asm
; Pseudo-code for coordinate transformation:
;
; 1. Load world coordinates
mov ax, [waypoint_x]        ; World X
mov bx, [waypoint_y]        ; World Y

; 2. Apply camera offset (pan)
sub ax, [camera_x]          ; X relative to camera
sub bx, [camera_y]          ; Y relative to camera

; 3. Apply zoom scaling
; zoom=1 means 1:1, zoom=2 means 2:1 (zoomed in)
mov cx, [zoom_factor]
; If zoom > 1, multiply (zoom in)
; If zoom < 1, divide (zoom out - but zoom is 1-999, so always multiply)
imul cx                     ; AX = (X - camera_x) * zoom

; 4. Add screen center offset
add ax, 160                 ; Center X (320/2)
add bx, 100                 ; Center Y (200/2)

; 5. Clip to screen bounds
cmp ax, 0
jl  clip_left
cmp ax, 319
jg  clip_right
cmp bx, 0
jl  clip_top
cmp bx, 199
jg  clip_bottom

; 6. Write to output record
mov [output_record+0], ax   ; screen_x
mov [output_record+2], bx   ; screen_y
mov byte ptr [output_record+4], 1  ; visible flag

; 7. Return
ret
```

#### Key Operations to Find

1. **Subtraction** - Camera offset
2. **Multiplication** - Zoom factor
3. **Division** - Scale down if needed
4. **Addition** - Screen center offset
5. **Comparison** - Clipping bounds (0-319, 0-199)
6. **Bit shifts** - Fast multiply/divide by powers of 2

#### Formulae to Extract

```
screen_x = ((waypoint_x - camera_x) * zoom) / scale + 160
screen_y = ((waypoint_y - camera_y) * zoom) / scale + 100

Where:
  waypoint_x, waypoint_y = world coordinates from .MIS file
  camera_x, camera_y = current pan position
  zoom = zoom factor (1-999)
  scale = normalization factor (depends on world coordinate range)
  160, 100 = screen center (320/2, 200/2)
```

```

  Camera at (500, 1500)

  screen_x = ((1000 - 500) * 1) / scale + 160
  screen_y = ((2000 - 1500) * 1) / scale + 100
  
Expected:

  Must be within 0-319, 0-199
```

### 2. Boundary Test
```
Test waypoints at:
  (0, 0) - Top-left corner
  (max_x, max_y) - Bottom-right corner
  
After transformation:
  Should map to screen edges or clip appropriately
```

### 3. Zoom Test
```
Same waypoint at different zoom levels:
  Zoom 1: Normal size
  Zoom 2: 2x size (objects appear bigger)
  Zoom 10: 10x size (highly zoomed in)
  
Screen coordinates should scale accordingly
```

### 4. Pan Test
```
Same waypoint, different camera positions:
  Camera at (0, 0): Waypoint appears right/down
  Camera at waypoint: Waypoint appears at screen center
  Camera beyond waypoint: Waypoint appears left/up
```
