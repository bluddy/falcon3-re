# Tactical Map Display Research - Falcon 3.0

## Overview

This document tracks reverse engineering of the Falcon 3.0 tactical map display system used in the mission editor (Nellis Command). The tactical map shows aircraft positions, waypoints, and flight paths with multiple zoom levels and 3D perspective.

**Status**: Initial research phase - identifying key functions and data structures
**Goal**: Understand coordinate transformation, graphics rendering, and map display pipeline (80-100% completion)

## Key Functions Identified

### 1. waypoint_coordinate_processor (0x1A2441)
- **Address**: 0x1A2441 (R63 segment)
- **Size**: 871 bytes (0x367)
- **Purpose**: Process waypoint coordinates for display
- **Evidence**: 8 waypoint accesses found (21-byte stride pattern)

### Waypoint Structure (21 bytes, 0x15)
**Documented in registry/structures.yaml**

From mission editor analysis:
```
Offset  Size  Type      Name          Description
------  ----  --------  ------------  ------------------------------------
0x00    1     uint8_t   marker        Always 0x01 (waypoint record marker)
0x01    4     int16_t   x_coord       X coordinate (signed, 2 bytes)
                        y_coord       Y coordinate (signed, 2 bytes)
0x05    6     ???       unknown       Duplicate or extended data
0x0B    10    ???       duplicate     10-byte duplicate of main structure
```

**Array Location**:
- Segment: 0x4FC2
- Offset: 0x168
- Linear address: 0x4FD88
- Element stride: 21 bytes (0x15)

    ↓

## Graphics Primitives Identified

### Core Drawing Functions

#### graphics_line_draw_bresenham (0x028B08)
- **Size**: 409 bytes
- **System**: HUD
- **Algorithm**: Bresenham line drawing (classic rasterization)
- **Purpose**: Draw lines between two points
- **Usage**: Flight paths, waypoint connections, HUD elements
- **Status**: Named in registry, needs disassembly

#### draw_from_struct (0x02245A)
- **Size**: 104 bytes
- **System**: Draw
- **Calls**: 649 times (heavily used!)
- **Purpose**: Dispatcher - coordinates+attributes → draw callbacks
- **Callees**: draw_struct_args_dispatch (0x0224C2)
- **Status**: Named in registry, needs analysis
- **Key Pattern**: Loads 5-word struct from [SI], dispatches via cs:22084

#### graphics_rect_fill_tiled (0x014200)
- **Size**: 106 bytes  
- **System**: HUD
- **Purpose**: Rectangle fill with 8×8 tile patterns
- **Features**: Clipping against viewport
- **Usage**: Map background, UI panels
- **Status**: Named in registry

#### font_glyph_bitmap_render (0x011AE7)
- **Size**: 62 bytes
- **System**: HUD/Font
- **Purpose**: Render text glyphs from bitmap font
- **Usage**: Labels, waypoint names, coordinates
- **Status**: Named in registry

### Line Drawing System

#### line_record_draw_loop (0x028E50)
- **Size**: 136 bytes
- **System**: Line
- **Purpose**: Walk line stream, prepare and draw each record
- **Callees**: 
  - rect_edge_dispatch_b
  - dispatch_220a4_near
- **Usage**: Draw multiple connected lines efficiently
- **Status**: Named in registry

#### line_record_flag_dispatch (0x0287A6)
- **Size**: 204 bytes
- **System**: Line
- **Purpose**: Unpack record flags, dispatch to draw operations
- **Callees**: 
  - state_flag_unpack_1f735
  - line_record_draw_loop
- **Usage**: Control line rendering (dashed, colored, etc.)
- **Status**: Named in registry

#### terrain_anim_line_object_draw (0x027A20)
- **Size**: 442 bytes
- **System**: Terrain
- **Purpose**: Animated line rendering (tracers, missiles)
- **Usage**: Dynamic objects, possibly waypoint animations
- **Status**: Named in registry

### Object/Sprite Drawing

#### object_proj_draw_dispatch (0x026B2E)
- **Size**: 244 bytes
- **System**: Object
- **Purpose**: Project 3D object points through view matrix
- **Usage**: 3D objects on tactical map (aircraft, ground objects)
- **Status**: Named in registry

#### farobj_rect_ratio_build (0x014CC6)
- **Size**: 396 bytes
- **System**: Farobj
- **Purpose**: Build ratio factors for projected blits
- **Usage**: Sprite scaling for distant objects
- **Calls**: 2,133 dynamic calls
- **Status**: Named in registry

### Clipping and Dispatch

#### clip_or_draw_dispatch (0x026099)
- **System**: Clip
- **Purpose**: Clip primitives to viewport, then dispatch draw
- **Callers**:
  - hud_draw_chain_step
  - rot_segment_strip_draw  
  - tile_strip_project_draw
- **Status**: Named in registry

- **Size**: 17 bytes

- **Status**: Named in registry

## Graphics Pipeline Architecture (Updated)

### Tactical Map Rendering Hypothesis

```
Tactical Map Display Request
    ↓
tactical_screen_coordinator (0x12DB6A)
    ├─ Setup viewport/zoom
    ├─ Calculate visible bounds
    └─ Call waypoint_display_processor
        ↓
waypoint_display_processor (0x1A0F10)
    ├─ Iterate waypoint array (0x4FC2:0x168)
    ├─ Build 18-byte input structures
    └─ Call waypoint_coordinate_processor (0x1A2441)
        ↓
waypoint_coordinate_processor (0x1A2441)
    ├─ Transform world → screen coordinates
    ├─ Apply zoom/perspective  
    ├─ Clip to viewport
    └─ Generate 6-byte display records
        ↓
Drawing Dispatcher
    ├─ draw_from_struct (0x02245A) ← 649 calls!
    │   └─ draw_struct_args_dispatch (0x0224C2)
    │       └─ cs:22084 dispatch table
    │
    ├─ For Waypoint Symbols:
    │   └─ graphics_rect_fill_tiled (0x014200) or sprite blit
    │
    ├─ For Flight Paths:
    │   └─ line_record_draw_loop (0x028E50)
    │       └─ graphics_line_draw_bresenham (0x028B08) ⭐
    │
    ├─ For Labels:
    │   └─ font_glyph_bitmap_render (0x011AE7)
    │
    └─ For Clipping:
        └─ clip_or_draw_dispatch (0x026099)
            ↓
VGA Buffer (segment 0xA000 or off-screen buffer)
```

### Draw System Call Flow

```
High-Level Render Function
    ↓
draw_from_struct(struct *draw_params) @ 0x02245A
    ├─ Extract 5-word struct: [x1, y1, x2, y2, attr]
    ├─ Validate coordinates
    └─ Call draw_struct_args_dispatch @ 0x0224C2
        └─ Dispatch via cs:22084 based on draw type:
            ├─ Type 0: Point/pixel
            ├─ Type 1: Line → graphics_line_draw_bresenham
            ├─ Type 2: Rectangle → graphics_rect_fill_tiled
            ├─ Type 3: Sprite/blit
            └─ Type N: Custom draw function
```
